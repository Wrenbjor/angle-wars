# Mobile build (Capacitor)

Angle Wars is wrapped for native iOS/Android with [Capacitor](https://capacitorjs.com/).
The native shells load the exact same production web bundle that `npm run build`
produces in `dist/` — there is **no** separate mobile codebase. Everything under
`src/` (gameplay, input, scenes, the Story 7.1 touch twin-stick controls, the
Story 7.2 safe-area handling) runs unchanged inside the native WebView.

## How it fits together

```
src/**  --npm run build-->  dist/  --npx cap sync-->  android/…/assets/public/
                                                      ios/App/App/public/
```

`capacitor.config.json` pins the identity and points Capacitor at the build:

| Key                    | Value                     |
| ---------------------- | ------------------------- |
| `appId`                | `com.wrenbjor.anglewars`  |
| `appName`              | `Angle Wars`              |
| `webDir`               | `dist`                    |
| `server.androidScheme` | `https`                   |

Whenever the web code changes, rebuild and re-sync:

```bash
npm run build     # regenerate dist/
npm run cap:sync  # copy dist/ into the native projects + update native deps
# (npm run cap:copy copies assets only, without the native-dependency update)
```

The copied web assets under `android/app/src/main/assets/public/` and
`ios/App/App/public/` are **regenerated by `cap sync`** and are gitignored by
Capacitor's per-project `.gitignore` — always run `npm run build && npm run cap:sync`
after a fresh clone before opening a native project.

## Android

### Prerequisites

- [Android Studio](https://developer.android.com/studio) (bundles the Android
  SDK + platform tools), **or** a standalone Android SDK with `ANDROID_HOME` set.
- **JDK 21+** (Capacitor 8's generated Android project compiles at Java 21 —
  see `sourceCompatibility`/`targetCompatibility` in `android/app/capacitor.build.gradle`;
  JDK 17 or older fails with `invalid source release: 21`).
- An Android emulator (AVD) or a physical device with USB debugging enabled.

### Build & run

```bash
npm run build
npm run cap:sync
npx cap open android          # opens the project in Android Studio
# — or, headless, from the SDK-equipped machine:
cd android && ./gradlew assembleDebug   # produces app/build/outputs/apk/debug/app-debug.apk
```

In Android Studio, pick a device/emulator and press **Run**. To install a CLI-built
APK: `adb install android/app/build/outputs/apk/debug/app-debug.apk`.

## iOS (macOS only)

### Prerequisites

- **macOS** with **Xcode** (from the App Store) and the Xcode command-line tools.
- **CocoaPods** (`sudo gem install cocoapods`).
- An iOS Simulator or a registered physical device.

### Build & run

The `ios/` base project is committed, but `Pods/` and `App.xcworkspace` are
generated by CocoaPods on macOS (they are gitignored). On a Mac:

```bash
npm run build
npm run cap:sync              # runs pod install as part of the iOS sync on macOS
npx cap open ios             # opens App.xcworkspace in Xcode
```

If prompted, run `cd ios/App && pod install` before opening. In Xcode, select a
simulator/device and press **Run**.

> **Note:** the iOS project in this repo was scaffolded on a Linux host, so the
> CocoaPods step (`Pods/`, `App.xcworkspace`) has not run. The first `cap sync`
> on macOS completes it. If the committed `ios/` template is ever incomplete,
> regenerate it on macOS with `npx cap add ios`.

## Manual end-to-end acceptance

The automated Vitest gate (`src/build/capacitorConfig.test.js`) proves the shell
wiring — config values, the `@capacitor/*` deps + `cap:*` scripts, the committed
Android project scaffold, and (once `npm run build && npm run cap:sync` has run)
the synced Android web bundle. On a clean checkout the synced bundle is gitignored
and absent, so the gate instead asserts the committed sync-target wiring; the
bundle itself is proven only after a build+sync or by the manual device run below.
The device run below **cannot** be automated on the Linux CI
host (no Android SDK, JDK 11, no macOS/Xcode) and must be verified by hand on a
properly equipped machine:

1. Build and sync: `npm run build && npm run cap:sync`.
2. Open and run on a device/emulator (`npx cap open android` or `npx cap open ios`).
3. Confirm the full loop inside the native WebView:
   - **Title** screen renders.
   - **Play** — the Story 7.1 touch twin-stick controls move the ship and aim/fire.
   - **Game over** appears on death.
   - **Restart** returns to a fresh run.
4. Confirm the canvas respects the device safe areas (notches/rounded corners),
   per Story 7.2.
