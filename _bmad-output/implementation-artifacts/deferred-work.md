  evidence: The HUD line reads `SCORE / MULT / BOMBS / LIVES / HIGH / XP / LV` with no dash entry; `snapshot().dash` publishes `enabled` but no `ready`, so the drawn button looks identical whether the dash is available or 2.9s away; and `AudioDirectorSystem`'s `_sfxOut = { fire, kill, spawn, bomb, death }` has no dash cue, though the smart bomb — the action the dash is documented as mirroring end-to-end — has one. A press during cooldown produces literally zero observable response: no sound, no motion, no UI change. The only rung with any activation feedback at all is Lv5, via the burning trail. Correctly out of scope on the intent's own authority — Story 10.5's Never list explicitly excludes "no HUD cooldown readout" — but the resulting gap has no owner anywhere in the plan, exactly like the Nanite Shield feedback entry above. `DashSystem.dashSeq` was published as a monotonic observability latch and is the hook such work would consume; no story claims it.

- source_spec: `spec-10-5-afterburner.md`
  summary: The touch overlay is drawn only while touch input is live, so a newly-granted dash button is invisible until the player is already touching something else.
  evidence: `ArenaScene.js:1552` gates the entire `drawTouchOverlay` call on `this.inputSampler.isTouchActive()`, clearing the graphics otherwise. Pre-existing and shared with the bomb, so not caused by this story — but Story 10.5 is where it first bites: the dash button is granted mid-run by a card pick, and the moment it appears is exactly the moment the player has no finger down to reveal it. A touch player picks Afterburner Lv2, the modal closes, and a 52px-radius disc of their right-half aim area silently starts routing to a control they cannot see at rest. The ownership gate the story added solves the never-unlocked case correctly; the just-unlocked case is a different problem and is untouched.

- source_spec: `spec-10-5-afterburner.md`
  summary: `ArenaScene`'s render-loop seams are pinned by regex over the file's own source text rather than by behavior, so the guards pass against a call that never runs.
  evidence: `renderIntegration.test.js` asserts call sites by matching the text of `ArenaScene.js` (`const arenaSrc = readSrc('./ArenaScene.js')`) for `setBombButton`, `setDashButton`, `setDashEnabled` and the modal drain. Each regex proves a line exists and is ordered; none can prove it executes, executes with a live value, or sits on the reachable side of an early return. All of them pass against a call placed inside `if (false)` or below a `return`. This is a pre-existing house pattern — the bomb's equivalents are pinned the same way, and `ArenaScene` genuinely needs a live Phaser context — but the tests' own comments record that the previously-missing dash wiring line "left the whole suite green", and the replacement reproduces that weakness one layer up. The real gap is that `ArenaScene.update()` has no behavioral test harness; a stub sampler plus stub systems driven through `update()` would retire the whole family of regex pins at once.
