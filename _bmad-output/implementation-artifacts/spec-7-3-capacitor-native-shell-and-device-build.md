## Intent

**Problem:** Angle Wars ships only as a static web bundle (`dist`). There is no native wrapper, so the finished, touch-capable game cannot be installed or run as a real iOS/Android app — Epic 7's whole point. Stories 7.1/7.2 already made the game touch-playable and safe-area-aware in the browser; this story wraps that same bundle in a native shell with no gameplay rewrite.

**Approach:** Add Capacitor as the native wrapper pointed at the existing production build. Create a `capacitor.config.json` whose `webDir` is `dist`, with a stable `appId` and display name; add the `@capacitor` dependencies and convenience scripts; generate the Android (and, best-effort on this non-macOS host, iOS) native projects and `npx cap sync` the built bundle into them; commit the native projects so Story 7.6 can customize icons/manifests later. Nothing under `src/` game code changes. The device-level "builds cleanly / runs end to end on a device" acceptance is anchored at the true surface but verified manually on a properly equipped machine (documented), because this Linux host has no Android SDK, no JDK 17, and no macOS/Xcode.

## Boundaries & Constraints

**Always:**
- `capacitor.config.json` MUST set `webDir: "dist"`, `appId: "com.wrenbjor.anglewars"`, `appName: "Angle Wars"`. `webDir` points at the Story 5.5 Vite output — never a copied/duplicated web tree.
- The Capacitor packages (`@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/ios`) MUST be declared in `package.json` at a single pinned major, and the lockfile updated.
- The Android native project MUST be generated on this host, committed, and MUST contain the synced web bundle (`dist` copied into `android/app/src/main/assets/public/`).
- Native projects are committed source (not gitignored) so later stories can edit manifests/icons; only per-platform build outputs (handled by Capacitor's generated per-project `.gitignore`) stay ignored.
- Zero changes to `src/**` game code, `vite.config.js` build output, or gameplay/input/scene systems. This is packaging only.

**Block If:**
- The Capacitor packages cannot be installed (npm registry unreachable) or `npx cap add android` fails to generate the Android project — without the Android shell there is no deliverable. HALT `blocked` with the failing command output.
- Wrapping would require editing `src/**` game logic to run inside the WebView (it must not). HALT `blocked`.

**Never:**
- Do not rewrite, port, or fork the game for native; do not introduce a second web bundle or change `dist` layout.
- Do not add in-app purchases, ads, app icons/splash, store manifests, native lifecycle/haptics, or a mobile performance profile — those are Stories 7.4/7.5/7.6.
- Do not claim iOS/Android device builds are verified here; do not fabricate emulator/device output.

## Design Notes

- **Why JSON, not TS, config.** The project is plain ES-module JS with no TS toolchain; `capacitor.config.json` is importable directly in the `node` vitest env, so its invariants get the same headless, executed pin as `vite.config.js` in `buildConfig.test.js` — no source-regex proxy needed for the config values themselves.
- **Why the device ACs are manual.** This host has `ANDROID_HOME` unset (no Android SDK), JDK 11 (Capacitor Android wants 17+), and no macOS/Xcode. `npx cap add android` only *scaffolds* (no SDK needed) and `cap sync` only *copies* assets, so both run here and are the automated gate; compiling an APK/IPA and running on a device physically cannot happen on this host. Anchoring the device AC at a headless proxy would be dishonest, so it is kept at the true surface and marked manual with exact commands — the established pattern for surfaces this repo cannot execute headlessly (cf. Story 7.2's manual checks).
- **iOS best-effort.** `cap add ios` copies the platform template before it attempts `pod install`; on Linux the copy succeeds and the CocoaPods step is skipped/failed. Commit the base template if produced; `Pods/` and `App.xcworkspace` are generated by `pod install` on macOS (Capacitor gitignores them by default). If nothing usable is produced, document iOS as generate-on-mac; this is not a block (Android is the proven-here platform).
