## Intent

**Problem:** Story 10.1 landed the item framework but registered every item with an empty `stats: {}`, so Overcharge — the rarity-5 offense item and the common fusion key — is a pickable card that does nothing. The `PlayerStats` fold produces `damageMult`/`fireRateMult`, but no gameplay system reads either: `FiringSystem` fires on the constant `FIRE_INTERVAL_MS` and `CollisionSystem` decrements armored `hp` by a hardcoded `1`. There is no player-bullet damage value at all — damage is an implicit "1 per hit" baked into the collision branch.

**Approach:** Author Overcharge's five per-level `stats` maps (the PRD §13.3 numbers), name the implicit damage unit as a `PLAYER_BULLET_BASE_DAMAGE` constant, stamp each spawned bullet with `base × damageMult`, have `CollisionSystem` decrement `hp` by the hitting bullet's damage instead of `1`, and derive the fire cadence from `FIRE_INTERVAL_MS / fireRateMult`. Both reads come from the one `playerStats` object `buildArenaWorld` already creates and `LevelUpSystem` already folds — no new state, no new system.

## Boundaries & Constraints

**Always:**
- Overcharge's `levels[].stats` are FRACTIONAL BONUSES onto the fold's base of 1, per the `PlayerStats.js` AUTHORING CONVENTION: L1 `{damageMult:0.15}`, L2 `{damageMult:0.25, fireRateMult:0.10}`, L3 `{0.35, 0.20}`, L4 `{0.45, 0.30}`, L5 `{0.60, 0.40}`. Each level's map is the TOTAL at that level, not a delta. Every `levels[].desc` string stays exactly as registered — the numbers must agree with the text already shipped.
- A bullet carries its `damage`, stamped ONCE at spawn from `PLAYER_BULLET_BASE_DAMAGE × playerStats.damageMult`. An in-flight bullet keeps the damage it was fired with; a mid-run upgrade never retroactively strengthens bullets already on screen.
- `CollisionSystem` decrements a finite-`hp` enemy by the HITTING BULLET's damage: the enemy survives when `hp > damage` (`hp -= damage`), and is killed on the existing unchanged kill path otherwise. An enemy with no `hp` field is one-shot exactly as today — damage never changes one-shot behavior in either direction.
- With no Overcharge owned (`damageMult === 1`, `fireRateMult === 1`) every shipped behavior is byte-for-byte identical to today: same cadence, same hits-to-kill, same bullet spawn positions/velocities. A bullet reaching `CollisionSystem` with a missing/non-finite/non-positive `damage` falls back to `PLAYER_BULLET_BASE_DAMAGE`, so existing fixtures and any non-`FiringSystem` bullet source keep the v1 one-hit-one-unit contract.
- The effective fire interval is `Math.max(FIRE_INTERVAL_FLOOR_MS, FIRE_INTERVAL_MS / fireRateMult)`, recomputed per tick from the live store. A non-finite or non-positive multiplier (either one) is sanitized to `1` before use. The floor is a SAFETY guard on the `while (_accumMs >= interval)` spawn loop, never a balance lever.
- Zero per-frame allocation in `FiringSystem.fixedUpdate` and `CollisionSystem.fixedUpdate` is preserved: no new per-tick objects, closures, or arrays. `CollisionSystem`'s hit-tracking structures stay reusable and pre-cleared.
- `FiringSystem` and `LevelUpSystem` read the SAME `playerStats` object instance from `buildArenaWorld`; the fold mutates in place, so the reference is captured once at construction.

**Block If:**
- Applying per-bullet damage to the `hp` path cannot preserve the existing armored regression expectations (`ARMORED_HP` hits to kill, one decrement per hit, one-shot enemies unaffected) at `damageMult === 1`.

**Never:**
- Do NOT change `CollisionSystem.bulletDamageCount` (still 1 integer per damaging hit) or touch `DpsTelemetrySystem` / `DPS_DAMAGE_PER_KILL`. Crediting fractional damage to the DPS ring would re-tune the Story 9.2 governor (`SPAWN_DIRECTOR_DPS_PRESSURE_REFERENCE` was calibrated against hits/sec) and re-open the float-drift hazard already logged against `spec-9-1`. Log it to `deferred-work.md` instead. Overcharge's fire-rate rungs already reach the governor honestly, via more hits/sec.
- Do NOT author `stats` for Spread Cannon, Nanite Shield, or Afterburner (stories 10.3–10.5), and do NOT add fields to `PLAYER_STATS_BASE` beyond the `damageMult`/`fireRateMult` already declared there.
- Do NOT change the AoE/melee paths (`BombSystem`, `BlackHoleSystem`) — they release enemies unconditionally, ignoring `hp`, and that full-damage asymmetry (FR33) is unchanged.
- Do NOT change Phaser/render code. The armored durability disc already derives from `s.hp / ARMORED_HP` and reads correctly with a fractional `hp`; the level-up overlay still renders `title` only (the per-level `desc` render stays deferred).
- Do NOT change bullet spawn geometry, `BULLET_SPEED`, the aim-independence guarantee, the pool prewarm, or `shotsFiredCount` semantics.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| No Overcharge owned | `playerStats` at base (`damageMult:1`, `fireRateMult:1`) | Cadence is exactly `FIRE_INTERVAL_MS`; each bullet's `damage === PLAYER_BULLET_BASE_DAMAGE`; an `ARMORED_HP` enemy takes exactly `ARMORED_HP` hits | No error expected |
| Overcharge fold, each level | `ownedCards.overcharge = 1..5`, folded via `recomputePlayerStats` | `playerStats` equals base + that level's map exactly (L1 `1.15`/`1.0`, L2 `1.25`/`1.10`, L3 `1.35`/`1.20`, L4 `1.45`/`1.30`, L5 `1.60`/`1.40`) | No error expected |
| Fire rate applied | `fireRateMult = 1.4`, aim held for T ms | Shots ≈ `T / (FIRE_INTERVAL_MS / 1.4)` — strictly more than at base over the same T | No error expected |
| Damage applied to armor | `damageMult = 1.25`, bullet hits `hp = ARMORED_HP (5)` | `hp` drops by `1.25` per hit; killed on the 4th hit (`ceil(5/1.25)`), not the 5th | No error expected |
| One-shot enemy | Any `damageMult`, enemy with no `hp` field | Killed on the first hit, reported in `killedEnemies`/`bulletKillCount` with its coord/XP snapshots — unchanged | No error expected |
| Two bullets, one enemy, one tick | Both overlap the same armored | Exactly ONE bullet is consumed against it and `hp` drops by exactly one bullet's damage; the other bullet stays active | No error expected |
| Bullet with no `damage` field | Hand-built fixture bullet (no `damage`), or `damage` NaN/0/negative | `CollisionSystem` applies `PLAYER_BULLET_BASE_DAMAGE` | Fallback, no throw |
| Degenerate multiplier | `fireRateMult` is `0`, negative, `NaN`, or `undefined` | Sanitized to `1` → cadence is exactly `FIRE_INTERVAL_MS`; the spawn loop always terminates (never a zero/negative interval) | Sanitized, no throw, no hang |
| Upgrade mid-run | Overcharge picked while bullets are in flight | Already-spawned bullets keep their old `damage`; the next spawned bullet carries the new value; cadence tightens from the next tick | No error expected |
| Assembled world | `buildArenaWorld()` → fold an owned Overcharge into the ctx `playerStats` | The firing system observes it through the SAME object (cadence + stamped damage change with no re-construction) | No error expected |

## Design Notes

Where the numbers land, and what is (deliberately) invisible:

- **Fire rate is immediately observable** at every level from Lv2 up — it is a global cadence change against every enemy.
- **Damage is observable only against the Armored archetype**, the game's only `hp` bearer (black holes are radius-based since 6.2; mirror reflectors are immune). With `ARMORED_HP = 5`, hits-to-kill is `ceil(5 / damageMult)`: Lv1's `1.15` still takes 5 hits, and Lv2–Lv5 all take 4. So Overcharge's damage rung is a no-op at Lv1 and saturates at Lv2 against shipped content. That is what the PRD numbers produce against the current one-shot roster — a balance observation for the ledger, not a defect, and it resolves as Epic 11 lands HP-bearing content.

The fold-to-seam path, end to end (all of it already exists except the two reads):

```js
// itemRegistry.js — L2 entry
{ level: 2, desc: '+25% damage / +10% fire rate',
  stats: Object.freeze({ damageMult: 0.25, fireRateMult: 0.10 }) }
// → recomputePlayerStats folds onto base 1 → { damageMult: 1.25, fireRateMult: 1.10 }
// FiringSystem.fixedUpdate
const interval = Math.max(FIRE_INTERVAL_FLOOR_MS, FIRE_INTERVAL_MS / mult(fireRateMult));
b.damage = PLAYER_BULLET_BASE_DAMAGE * mult(damageMult);
// CollisionSystem pass 2
if (Number.isFinite(s.hp) && s.hp > dmg) { s.hp -= dmg; continue; } // else: kill path, unchanged
```

`_hitEnemies` becomes a `Map` rather than threading a parallel damage array, because pass 2 iterates ENEMIES (not bullets) and needs the damage of whichever bullet claimed each one; a reused `Map` keeps the zero-per-tick-allocation contract and leaves every `.has()` call site unchanged.
